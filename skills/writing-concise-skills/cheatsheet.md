# Cheatsheet — 决策速查

## 写 skill 前：三个体检问题

| 问题 | 不合格的答案 | 合格的答案 |
|---|---|---|
| 它补了什么上下文？ | "教模型怎么写代码" | "团队踩过的坑、领域惯例、验收标准" |
| 它守了什么门槛？ | 没有 | "没有可复现的验证就不许猜原因" |
| 它会被触发吗？ | 需要用户记得手动调才有价值 | 恰好出现在问题现场（Vercel 数据：56% 从未被调用） |

## 写作决策树

```
要写 skill？
├─ 是在教模型具体怎么做？ → 停。改写成责任状（目标+边界+验收）
├─ 内容超过一屏？ → 拆：主文件核心框架 + 章节按需加载（渐进式披露）
├─ 用户会自动想起用吗？ → 否。要么绑定触发场景，要么砍掉
└─ 规则会不会互相打架？ → 会。删到只剩关键缰绳
```

## 阈值与默认值

| 指标 | 标准 |
|---|---|
| 样板大小 | ≤ 12 行，一张截图放得下 |
| skill 数量 | 挑 2–4 个改成自己的，别全装 |
| 追问数量 | 逼出共识即停；连续追问会拖垮流程（Pocock issue #274） |
| 检验周期 | 装进流程两周后：在用的留下，积灰的删掉 |
| fork/star 比 | ≥8.6% 说明人们 fork 回去用（普通爆款 2–5%） |
| 安装量/star 比 | 40 倍+ 说明 star 低估真实规模 |
| 库规模红线 | 202 个 skill → 通过率 -21%（arXiv） |

## 决策规则（if/then）

- **模型很强** → 写责任，不写步骤
- **规则开始互相打架** → 删规则，不是加规则
- **上下文装不下** → 渐进式披露，不是压缩成一句废话
- **skill 没有被触发** → 价值为零，不管写得有多好
- **想传播 skill** → 单品（12 行样板）+ 元理论（方法论）+ 自有渠道反复推
- **想验证 skill 价值** → 看 fork/star 比、安装量、两周留存，不看 star 数

## Tells & Smells（识别信号）

- 看到"不许 X / 必须 Y"开头的长清单 → 紧箍咒，准备删
- SKILL.md 超过一屏还在讲"怎么做" → 在写教程，不是在写责任
- 安装后两周没碰过 → 收藏家心态，删
- 一个 skill 什么都做 → 违背单用途原则，拆
