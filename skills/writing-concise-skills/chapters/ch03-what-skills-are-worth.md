# Ch 3: Skill 值钱在哪 —— 补上下文，守门槛

## Core Idea
受欢迎的 skills 没有一条在教模型怎么写代码，它们只做两件事：补上下文，守门槛。

## Frameworks Introduced
- **双职责模型（Context + Gate）**：skill 的两个合法职能
  - 补上下文：提供模型现场看不到的经验（需求共识、领域知识、团队惯例）
  - 守门槛：在关键节点要求证据或验证，不让模型跳过判断
- **门槛（Gate）模式**：不替模型规划，只守一道门
  - When to use: 错误代价高的环节
  - How: 定义"通过"标准，不满足就不许前进

## Key Concepts
- **grill-me 式追问**：不聊实现，只聊需求；开工前逼出目标、边界、取舍，把"大概这样"逼成可执行共识
- **证据门槛**：diagnosing-bugs 的规则 —— 没有稳定、快速、能明确变红的验证方式，就不许猜原因
- **skill 不是越多越好**：202 个 skill 的库让 agent 通过率最多降 21%（arXiv）

## Mental Models
- 不是代替模型判断，而是在关键节点给经验和门槛
- 少即是多：工具的边界决定选型的准确度

## Anti-patterns
- **技能膨胀（skill bloat）**：装得越多，模型越容易选错工具
- **把 skill 写成教程**：教模型怎么写代码 = 既浪费又过时

## Key Takeaways
1. Skill = 团队经验的责任状 + 门槛
2. 好 skill 的两问：它补了什么上下文？它守了什么门槛？—— 都不是，就别写
3. 数据：202 个 skill → 通过率 -21%
