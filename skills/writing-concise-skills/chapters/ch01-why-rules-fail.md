# Ch 1: 为什么详细规则会失败（紧箍咒效应）

## Core Idea
给强模型写大量规则，护栏会变成紧箍咒：模型不是不会干，是不知道该听谁的。

## Frameworks Introduced
- **紧箍咒效应（Constriction Effect）**：规则从护栏变成限制的过程
  - When to use: 你在往 prompt / skill 里堆第 N 条规则时
  - How: 问自己 —— 这条规则是防止模型出错，还是只满足"规则感"？模型已经会看代码风格、猜意图、自己规划，教小孩式的规则会互相打架（"该补文档" vs "绝对别写注释"）

## Key Concepts
- **规则冲突**：System Prompt、Skills、用户指令各自带规则，互相矛盾时模型选择瘫痪
- **护栏 → 紧箍咒**：模型越强，同一条规则从保护变成束缚

## Mental Models
- 把模型当成长大了的同事，而不是需要逐条叮嘱的小孩
- 规则是缰绳：需要几根关键缰绳，而不是八百根绳子

## Anti-patterns
- **规则堆积**：每加一条规则，就多一分规则互斥的风险
- **教小孩式写作**：不许做 X、不许做 Y、做 Z 前先背例子 —— 强模型不需要也不耐受

## Key Takeaways
1. 规则不是越多越好，规则之间有冲突成本
2. Anthropic 的实践：删掉八成 System Prompt，评测没掉
3. 一句话替代一堆规则："写得像这个项目原本的代码"
