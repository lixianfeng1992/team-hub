# Ch 7: Key Take Aways —— 写精炼 skill 的行动清单

## Core Idea
给弱模型写步骤，给强模型写责任。写 skill 只有一句话：写责任，别写步骤。

## Frameworks Introduced
- **写作四步法（skill 创作者视角）**：
  1. 先做一个小样板：12 行就够，一张截图放得下，三句话讲明白
  2. 把方法论讲清楚：单品负责出圈，元理论负责留人
  3. 用自己的渠道反复推：渠道是自己的，发布才是可重复触发的事件
  4. 用数据校准：fork/star 比、安装量、两周留存

## Key Concepts
- **最小样板（12-line sample）**：能在一张截图里讲明白的 skill 才是好 skill
- **两周检验标准**：装进流程两周后还在用的留下，积灰的删掉
- **挑 2–4 个改造成自己的**：从最痛点下手（需求对不齐就装 grilling，测试乱写就装 tdd）；绑死工具链？MIT 许可，fork 回去换成自己的

## Mental Models
- 写责任，别写步骤：把工程判断写成责任状，把路线留给模型
- Prompt 不会复利，Context 才会
- 人负责目标、上下文、边界、证据和最终责任；路线交给模型自己找

## Anti-patterns
- **全装主义**：被 Vercel 和 arXiv 的数据追着跑的结论 —— 别全装
- **收藏家心态**：拥有不算数，用起来才算数

## Key Takeaways
1. 写 skill：先 12 行样板，再方法论，再反复推
2. 用 skill：挑 2–4 个，改成自己的，两周后检验
3. 未来值钱的系统：持续沉淀真实业务现场，又敢把多余控制一层层删掉
4. Skill 之争本质是身份之争：写步骤的会像操作工，写责任状的像指挥官
